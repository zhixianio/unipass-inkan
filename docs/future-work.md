# 后续计划（未实现）

> 这里记的是已经想清楚、但还没做的部分。是否实现看文章发出后的反响（2026-10-27）。

## 1. YubiKey 作为长期保存的 owner

**动机**：手机电池会老化、系统会过时，不适合在保险箱里放很多年。YubiKey 没有电池、耐摔、防水，适合当长期保存的备用 owner。

**为什么容易接入**：YubiKey 的 FIDO2 凭证就是 P-256 的 WebAuthn 签名（ES256），密钥绑定在设备上、不可导出。Safe 的 WebAuthn signer proxy 原生就能验证它，**合约那一侧不用改**。签名格式见 `docs/webauthn-signature.md`。

**关键限制**：YubiKey 没有屏幕，对传给它的任何哈希都会签。所以**不能接在桌面端上**，否则等于盲签，而桌面端是不可信的。

**用法**：YubiKey 通过签名器手机签名。
1. 签名器照常扫码、解码、跑规则、显示确认页。
2. 用户确认后，手机通过 NFC 让 YubiKey 对同一个 safeTxHash 签名：在手机上输入 YubiKey 的 PIN（Safe 的验签要求 UV 位），再碰一下 YubiKey。
3. 两份签名（手机 Secure Enclave 的和 YubiKey 的）一起放进回传二维码。

**推荐组合**：iPhone 签名器 + YubiKey A（日常用）+ YubiKey B（放保险箱），2-of-3。
- 日常：iPhone 核验并签一份，YubiKey A 签一份。
- 手机丢了：在新手机上装签名器，用 YubiKey A + B 把旧手机移出、把新手机加入。YubiKey 的凭证设为可发现凭证，新手机碰一下就能找到，不用另外记凭证 ID。
- 想签名，必须同时有手机核验、实体 YubiKey、碰一下、输入 PIN。手机单独被攻破也凑不够阈值。
- 局限：交易的核验只在手机上做一次，不像两台独立签名器那样各自核验。链上 Guard（见第 3 节）可以弥补。

**要先验证的**（⚠️ 都没实测）
- 系统的 passkey 接口要求 RP ID 关联域名（AASA），我们已经放弃了 AASA。所以要绕开系统接口，用 CoreNFC 直接发 CTAP2 指令。可以用 Yubico 的开源 iOS SDK（YubiKit，Apache-2.0），也可以用 core 已有的 CBOR 自己实现最小版本。要确认 Apple 允许在 CoreNFC 里选择 FIDO 的 AID。
- 飞行模式下 NFC 能不能用。NFC 不产生 IP 连接，不影响联网检查。
- 用 YubiKey 真实签一笔 SafeTx，在 Sepolia 上执行。
- 二维码协议：`unipass-signature` 要能一次带多份签名。

Ledger 的 FIDO app 也能当 P-256 认证器，但通过 USB 或蓝牙连接，FIDO2 支持程度也没核实；Ledger 更适合直接当普通账户 owner，用它自己的清签。

## 2. Pixel 签名器

Android 的 StrongBox 加密钥证明，可以和 iPhone 组成跨厂商的多签：一家的系统或芯片出漏洞，不会同时伤到所有签名人；密钥证明还能让桌面端离线验证"这把密钥确实在安全芯片里"。v1 只支持 Pixel 8 及以后。合约和签名格式不用改，配对码要加一个可选的证明链字段。

## 3. 链上 Guard

签名器再聪明，用户也可能被社会工程骗得输入确认短语、照样签了，签名器的规则也可能有 bug。链上 Guard 不依赖任何人的判断：
- 委托调用只允许官方的 MultiSendCallOnly；
- 改 owner、阈值、guard、fallback handler、module 都要先提交、等一段时间才能执行；
- 等待期内，任意一个 owner 签一条取消消息就能否决。

设计说明见 `docs/guard-design.md`（进行中）。

## 4. 用 Safe 的退款机制让提交账户自给自足

现在提交账户要偶尔手动充值。Safe 的 `execTransaction` 自带退款：SafeTx 里的 `gasPrice` 不为 0 时，执行后按 `(gasUsed + baseGas) × min(gasPrice, tx.gasprice)` 从 Safe 余额退 ETH 给 `refundReceiver`。用它可以让提交账户只放一笔初始的钱，之后由 Safe 自己报销 gas。

但签名器现在对退款字段一律硬拒（被篡改的桌面端可以借"退款"转走 Safe 的钱）。要支持退款，必须改成"有上限地放行"：
- 只允许退 ETH（`gasToken` 为零地址），`refundReceiver` 必须是已登记的提交账户；
- 签名器对 `gasPrice` 和 `baseGas` 设绝对上限，并显示"最多从 Safe 扣约 X ETH 作为网络费"。签名器离线，不知道当时的 gas 价格，只能用绝对上限；
- 剩余风险：桌面端本身握着提交账户的密钥，被控制时每笔交易都可能按上限多扣，所以上限要设得保守；
- 提交账户仍要先垫付一笔的 gas，退款在执行之后才到。

### 主网和测试网用不同的提交账户私钥

现在三条链共用一把提交账户私钥。现在已经要求节点报的 chainId 等于目标链、白名单按 (链, 地址) 匹配，谎报 chainId 签不出别的链的交易；分开私钥是再多一层：测试网上的任何问题都碰不到主网的余额。要改的是钥匙串条目按"主网 / 测试网"各一份，设置页分开显示地址和余额。

## 5. Safe 用自己的余额付 gas（ERC-4337）

Sepolia 上已经跑通（用的是软件 P-256 测试密钥），这一版没有采用。

## 6. 抗量子的 owner（ML-DSA）

只是想法，还没调研。P-256 和 secp256k1 都会被足够大的量子计算机破解。以后可以给 Safe 加一个抗量子签名（例如 ML-DSA）的 owner，再逐步替换现有 owner。要先弄清楚：手机安全芯片能否生成并保管这种密钥；链上怎么验证（目前没有预编译，纯合约验证的 gas 可能很高）；签名和公钥都比 P-256 大得多，二维码要传的数据会多很多。

## 7. 自定义代币

现在两端只认 core 内置标签库里的代币（每一条都注明来源：主网 13 个 ERC-20、Base 11 个、Sepolia 3 个）。计划：
- 桌面端按合约地址添加代币，从链上读 name / symbol / decimals，标明"自定义"；
- 签名器离线，没法核实桌面端给的名称和小数位，不在内置列表里的代币照旧按 R09 标黄"不认识的代币"，显示合约地址；
- 之后可以像地址簿一样，让用户在签名器上确认一次后记住某个代币（名称和小数位由用户在手机上核对）。

## 8. 在桌面端换签名人、改阈值（下一步）

手机丢了、换新手机、加 YubiKey，都要"移除旧签名人、加新签名人"或改阈值。签名器已经能解码这类交易（`addOwnerWithThreshold` / `removeOwner` / `swapOwner` / `changeThreshold`，R02），并显示前后对比；缺的是桌面端的入口：设置 › 签名器与 Safe 里的"更换签名人""添加签名人""修改阈值"。

配套要做"导出 / 导入 Safe 列表"：现在"添加已有 Safe"只接受创建后没改过配置的 Safe（签名器离线，只能信创建参数），一旦换过签名人，换一台 Mac 就加不回来。导出文件要带上创建参数和之后每次配置变更的记录，导入时逐条核对链上状态。签名器那边对应的问题：它登记的签名人列表要在签过的配置变更之后跟着更新。
